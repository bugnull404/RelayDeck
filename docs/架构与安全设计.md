# RelayDeck 架构与安全设计

## 组件

```text
Android App
  |
  | HTTPS（局域网 / EasyTier / 直连）
  | 或 WSS + 端到端加密（Relay）
  v
Windows RelayDeck Gateway（127.0.0.1:9443）
  |
  v
Codex Desktop 本地接口
```

Relay 模式：

```text
Android --WSS--> Relay <--WSS-- Windows Relay Agent --> 127.0.0.1:9443
```

## 身份与配对

- 手机首次通过一次性 ticket 注册。
- ticket 有有效期，只能成功使用一次。
- 配对完成后，手机使用长期设备凭据。
- Relay 只保存设备凭据的 SHA-256 摘要。
- Windows 配置中的敏感值使用 DPAPI 加密。
- 每个设备的访问范围由电脑端授权配置限制。

## Relay 加密

1. 手机与 Windows Agent 通过 Relay 交换临时公钥。
2. 双方使用 P-256 ECDH 派生共享秘密。
3. 通过 HKDF 派生双向 AES-256-GCM 密钥。
4. 每个方向使用独立 sequence，并放入 AAD。
5. Relay 只看到会话路由、密文和有限的帧元数据。
6. Gateway Bearer Token 只出现在内层加密请求中。

Relay 的注册密钥只用于电脑 Agent 向 Relay 注册，不进入手机配对二维码。

## 网络边界

- Gateway 默认只监听 `127.0.0.1:9443`。
- 本机 Relay 默认只监听 `127.0.0.1:19647`。
- 公网入口必须由 TLS 反向代理、frp HTTPS/vhost 或其他安全隧道提供。
- 不建议把明文 `ws://` 暴露到公网。
- 防火墙只需开放实际使用的公网入口。

## 信任边界

- Relay 运营商可以看到连接时间、机器 ID、会话 ID 和流量大小。
- Relay 运营商不应获得聊天正文、文件内容、Gateway Token 或设备凭据。
- Windows 电脑是最终授权点。
- 手机被撤销后，不能继续使用旧设备凭据。

## 数据目录

```text
%LOCALAPPDATA%\RelayDeck\
  config.local.json
  manager.local.json
  secrets\
  relay\
```

不要在日志、发布包或公开聊天中输出：

- Relay 注册密钥
- EasyTier 网络密钥
- Gateway Bearer Token
- TLS 私钥
- 完整配对 JSON
- Android 签名文件

## 兼容性

RelayDeck 使用自己的：

- Android 包名：`dev.relaydeck.mobile`
- 插件 ID：`relaydeck-desktop`
- marketplace：`relaydeck-local`
- URL scheme：`relaydeck://`
- 数据目录：`%LOCALAPPDATA%\RelayDeck`
- Relay 协议标识：`relaydeck-relay-v1`
- 发布资产前缀：`relaydeck-`、`relaydeck-desktop-`

这些标识共同构成 RelayDeck 的独立命名空间。
