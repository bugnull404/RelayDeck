# RelayDeck 开发与发布约定

## 版本

RelayDeck 从 `0.1.0` 独立起步，当前版本为 `0.1.2`。版本来源只有 `release.json`：

```json
{
  "version": "0.1.2",
  "versionCode": 3,
  "easytierVersion": "2.6.4"
}
```

`package.json`、插件清单和构建产物必须与 `release.json` 一致。

## 标识

| 项目 | 固定值 |
| --- | --- |
| Android 包名 | `dev.relaydeck.mobile` |
| Android 应用名 | `RelayDeck` |
| 插件 ID | `relaydeck-desktop` |
| marketplace | `relaydeck-local` |
| 数据目录 | `%LOCALAPPDATA%\RelayDeck` |
| URL scheme | `relaydeck://` |
| Relay 协议 | `relaydeck-relay-v1` |
| Android APK | `relaydeck-<版本>.apk` |
| Windows ZIP | `relaydeck-desktop-<版本>.zip` |

这些标识是 RelayDeck 的发布约定，修改时必须同步升级版本并验证兼容性。

## 发布资产

Release 标签使用 `v<主>.<次>.<补丁>` 或 `v<主>.<次>.<补丁>-<后缀>`。

每个正式 Release 应包含：

- `relaydeck-<版本>.apk`
- `relaydeck-desktop-<版本>.zip`
- 对应的 `docs/release-<版本>.md`

更新元数据格式：

```html
<!-- relaydeck-update: {"minDesktopVersion":"0.1.2"} -->
```

## 构建

```powershell
npm ci
npm test
npm run verify:release
.\scripts\build-desktop-plugin.ps1
.\scripts\build-android.ps1 -SdkPath <SDK> -JavaPath <JDK17> -GradlePath .\android\gradlew.bat -UpdateRepo <owner/repository>
```

`-UpdateRepo` 用于把 GitHub Release 检查绑定到明确的仓库。省略时更新检查关闭，不使用占位符或隐式默认仓库。

## 测试

- Node 测试覆盖 Gateway、配对、Relay、桌面管理和协议。
- Android JVM 测试覆盖状态解析、更新策略和组网参数。
- 发布前必须验证 APK 签名、版本号和敏感文件扫描。
- 真实公网 Relay、frp 和手机网络切换应单独做人工验收。

## 发布包检查

发布包不得包含：

- `.local`
- `secrets`
- TLS 私钥、证书私钥
- Android keystore
- Relay 注册密钥
- 完整配对 JSON
- 本机配置

## 安全

- 不修改 Codex 数据库或 rollout 文件。
- 不替换 Codex 桌面二进制。
- 不强制获取 Codex writer lock。
- 不为探测停止用户已有的 Codex 或 EasyTier 进程。
- 只管理 RelayDeck 明确启动的 EasyTier 实例。
- Relay 注册密钥只保存在 DPAPI 加密配置和 Relay 本机配置中。
