# RelayDeck 接口验证

本文说明 RelayDeck 如何验证本机 Codex 接口，以及发布前应区分哪些结论。它不是某台电脑的固定验证报告，也不包含聊天内容、账号信息、机器路径或任何凭据。

## 验证原则

- 以当前安装的 Codex 桌面程序为准，不以 PATH 中的 npm CLI 代替。
- 只读历史读取成功，不等于已经接入桌面当前运行实例。
- 不强制获取 writer lock，不修改 Codex 数据库或 rollout。
- 不替换 Codex 桌面程序，也不为探测停止用户已有的 Codex 或 EasyTier 进程。
- 机器相关结果只写入被忽略的 `.local/verification/`。

## 自动检查

仓库提供以下只读或隔离验证脚本：

```powershell
npm test
npm run verify:release
node .\scripts\verify-desktop-ipc.mjs
node .\scripts\verify-desktop-native.mjs
node .\scripts\verify-gateway.mjs
node .\scripts\verify-history-sync.mjs
node .\scripts\verify-interfaces.mjs --codex "<Codex 桌面程序路径>"
node .\scripts\verify-local-chat.mjs --codex "<Codex 桌面程序路径>"
```

其中：

- `verify-desktop-ipc.mjs` 检查当前桌面 Codex 的本机 IPC 是否可用。
- `verify-desktop-native.mjs` 检查插件绑定的桌面程序版本与发布元数据。
- `verify-gateway.mjs` 检查 HTTPS 网关、配对和鉴权行为。
- `verify-history-sync.mjs` 检查持久化历史读取，不把读取结果表述为实时同步。
- `verify-interfaces.mjs` 检查安装版 app-server 的初始化、thread 目录和只读方法。
- `verify-local-chat.mjs` 在临时目录创建单个带标记的持久测试 thread，验证发送、流式事件、历史与恢复；没有公开删除接口时需从 Codex 列表手工清理该测试 thread。

## 人工验收

发布前至少完成：

1. 使用当前桌面 Codex 打开插件设置。
2. 生成一次性二维码，用 Android 手机完成配对。
3. 查看会话列表并打开一个已授权会话。
4. 发送一条短任务，确认手机端收到状态变化和完成结果。
5. 触发一次审批，确认手机端可以处理。
6. 切换局域网、已有组网、内置 EasyTier、Relay 或直连模式，确认不会串用配置。
7. 撤销手机授权，确认该手机不能继续访问。
8. Relay 模式额外验证断网重连、长期设备凭据和 `wss://` 公网入口。

## 结论口径

| 已观察到的结果 | 可以表述为 |
| --- | --- |
| 能列出或读取持久化聊天 | 历史可读取 |
| 收到当前桌面实例的实时增量 | 当前桌面实例已接入 |
| 手机发送的任务出现在同一桌面会话 | 已实现同一会话双向操作 |
| 只核对协议 schema | 接口已定义，未完成端到端验证 |

## Chat 会话边界

- `thread/list` 返回的是 Codex thread；`ThreadSourceKind` 只覆盖 CLI、IDE、app-server、子代理等 Codex 来源。
- `chatgpt_handoff` 表示 ChatGPT 对话被引用进 Codex 后形成的工作 thread，RelayDeck 会以“Chat 引用”标记展示，不能把它称为 Chat 原会话同步。
- 普通 ChatGPT Chat 会话由 ChatGPT 云端管理，不在 Codex 的 `thread/list` 中；当前没有可用的官方 app-server 列表或消息读取接口。
- 不应通过读取认证令牌、调用未公开后端、抓取网页 DOM 或直接修改 Codex 数据库来实现 Chat 同步。

## Codex 本地对话接口

RelayDeck 另建一个长期存活的 app-server 子进程，只管理 RelayDeck 创建的本地 thread：

| 操作 | 公开方法 |
| --- | --- |
| 创建持久 thread | `thread/start` |
| 发送一轮消息 | `turn/start` |
| 执行中追加 | `turn/steer` |
| 停止 | `turn/interrupt` |
| 恢复 | `thread/resume` |
| 读取逐轮历史 | `thread/turns/list` |
| 修改模型 | `thread/settings/update` |
| 流式回复 | `item/agentMessage/delta` 等通知 |
| 审批与用户问题 | app-server 服务端请求 |

手机只调用 `POST /v1/chats/new` 并以已有会话 ID 指定项目来源；电脑端从目录解析 `cwd`，不接受手机传入任意绝对路径。新对话使用 `ephemeral:false`，否则历史无法持久保存。这个通道创建的仍是 **Codex 本地 thread**，不是 ChatGPT 原 Chat。

完整的列表、发送与实时同步验证边界见 [Chat 同步验证](Chat同步验证.md)。

本地对话的真实二进制验收使用：

```powershell
node .\scripts\verify-local-chat.mjs --codex "<Codex 桌面程序路径>"
```

该脚本不接受现有 thread ID，也不会打开或写入现有会话。它只创建一个临时 cwd 下的 `RelayDeck verification (temporary)` thread，并在报告中返回其 ID。由于公开 app-server 没有 `thread/delete`，测试完后需要从 Codex 桌面列表手工删除。

真实公网 Relay、frp、跨运营商网络和手机锁屏通知必须单独做人工验收。自动测试通过只说明仓库内实现符合当前测试约束，不替代真实网络与真机验证。
